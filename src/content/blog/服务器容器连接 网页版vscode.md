偶尔 vscode 直接远程会有奇奇怪怪的问题（并且我也不知道怎么解决）。

于是可以使用这样的替代方案：

容器里安装并启动code-server

```bash
curl -fsSL https://code-server.dev/install.sh | sh
code-server --bind-addr 0.0.0.0:8080 --auth none
```

容器内运行下面命令查容器 IP：
```bash
hostname -i
```
笔记本上：

```bash
ssh -L 8080:容器 IP:8080 用户名@宿主机ip
```

浏览器打开http://127.0.0.1:8080即可。

这里的逻辑是：

```
Mac:8080
    ↓ SSH
宿主机
    ↓
容器IP:8080
```

这里是 ssh 的端口转发（隧道功能）。

共有

- 本地端口转发 -L
- 远程端口转发 -R
- 动态端口转发 -D

三种。

## 本地端口转发

考虑这样的场景：
三台主机 ABC，A→C，某服务不可直连，B→C，某服务可直连，A→B，SSH可直连。
要做到 A→C，某服务的间接连接。

则使用这样的命令：
```bash
ssh -L 收听端口:主机CIP:目标端口 主机B用户名@主机BIP
```
其中收听端口是主机 A 上任意未使用的端口，目标端口是主机 C 上该服务的端口。

常见场景为主机 C是主机 B 上运行的虚拟机、docker 容器等。

## 远程端口转发

考虑这样的场景：
三台主机 ABC，B→C，某服务不可直连，A→C，某服务可直连，A→B，SSH可直连。
要做到 B→C，某服务的间接连接。

则使用这样的命令
```bash
ssh -R 收听端口:主机CIP:目标端口 主机B用户名@主机BIP
```
其中收听端口是主机 B 上任意未使用的端口，目标端口是主机 C 上该服务的端口。

常见场景为主机 B 想要使用主机A 上的代理，此时主机 C 就是主机 A 的 localhost，主机CIP为 127.0.0.1，目标端口为主机 A 上的代理端口。（注意，这里 B 不能直接访问 C，因为 C 是 A 的 localhost，只能由 A 来访问。）
如果进一步想要主机 B 上的虚拟机/docker 容器使用 A 上的代理，再做一次转发即可，这里就与 ssh无关。
